What is MongoDB and why would you use it instead of MySQL?

MongoDB is a NoSQL database that stores data in JSON-like documents instead of tables and rows.
MySQL is a relational SQL database that stores data in tables with rows and columns.


I would choose MongoDB when:

The data structure changes frequently.
I need a flexible schema.
I have large amounts of unstructured or semi-structured data.

MYSQL DATA

id | name | age
1  | John | 25


MongoDB:

{
  _id: 1,
  name: "John",
  age: 25
}

What is BSON?

MongoDB stores documents in BSON format.
BSON stands for Binary JSON.

JSON:

{
  "name": "Rohan",
  "age": 28
}

MongoDB's  _id is commonly an ObjectId
ObjectId() is a BSON-specific type.

{
  _id: ObjectId("6a91a57eb13baa0f5af0b430"),
  name: "Rohan",
  age: 28
}

What is a document and a collection in MongoDB?

A document is a single record in MongoDB,
document is similar to a row in MySQL. 

Collection is a group of documents. 
A collection is similar to a table,

MySQL:                            MongoDB:
Database → Table → Row            Database → Collection → Document

What is Mongoose?

Mongoose is an ODM (Object Data Modeling) library for MongoDB and Node.js.
Mongoose makes it easier for your Node.js/Express application to work with MongoDB.

with mongoose we can create a model
const User = mongoose.model("User", userSchema);

Mongoose gives you features like:

Schema → define the structure of documents
Validation → required fields, min/max, etc.
Models → interact with collections
Middleware/hooks → pre, post

what is schema?


A schema defines the structure, data types, and validation rules for documents

A schema defines the structure and rules for your data.
schema tells your application:

What fields a document should have
What type each field should be
Which fields are required
Validation rules
Default values, etc.

This schema says:

User
 ├── name  → String → required
 ├── age   → Number → required
 └── email → String → required + unique

 you want to store users:

 const userSchema = new mongoose.Schema({
  name: {
    type: String,
    required: true
  },
  age: {
    type: Number,
    required: true
  },
  email: {
    type: String,
    required: true,
    unique: true
  }
});

you create a model from the schema:

const User = mongoose.model("User", userSchema);

What is the difference between updateOne(), updateMany(), and replaceOne()? 

updateOne()
Updates only the first matching document.

db.users.updateOne(
  { name: "John" },
  { $set: { age: 30 } }
);

Only one John will be updated.

------------------------------------------------------------------------------

updateMany()
Updates all matching documents.

db.users.updateMany(
  { city: "Mumbai" },
  { $set: { country: "India" } }
);

All users from Mumbai will be updated.

----------------------------------------------------------------------------

replaceOne()
Replaces the entire document with the new document.

db.users.replaceOne(
  { name: "John" },
  { name: "John", age: 30, city: "Mumbai" }
);

The old document is completely replaced. 
Fields that aren't included in the new document are removed.


----------------------------------------------------------------------------
Method	What it does
updateOne()	Updates one matching document
updateMany()	Updates all matching documents
replaceOne()	Replaces the complete document
