1) They may ask?

i)Why did you use MongoDB in your assignment?

MongoDB integrates well with Node.js using Mongoose, 
and I'm comfortable working with it as part of the MERN stack. 
Since the assignment allowed any database, 
I felt MongoDB was a suitable choice for this use case.

ii)If they ask: "Why not MySQL?"

MySQL would also work. 
I would prefer MySQL when the application has complex relationships,
joins, or strong relational constraints. 
For this assignment, the data is relatively 
simple and document-based, so MongoDB was sufficient.

2) What is a REST API?

REST stands for Representational State Transfer. 
It is an architectural style for designing APIs where 
resources are accessed using HTTP methods 
such as GET, POST, PUT, PATCH, and DELETE

3) Explain the flow of your assignment.

   The user enters their first name, last name, and date of birth in
   React frontend. When the form is submitted, the frontend 
   sends the data to the Node.js backend through the 
   POST /user API. The backend validates the data, 
   checks whether the user already exists, and calls the Dog 
   API to get a random dog image. 
   Then it stores the user information and the image URL in MongoDB. 
   When the frontend requests GET /user, 
   the backend retrieves the users and calculates the age from the 
   stored date of birth before returning the response.

4) Why calculate age instead of storing it?

Because age is a changing value, while date of birth is permanent. 
If I stored age, it would become outdated over time. 
So I stored the DOB and calculated the 
current age when retrieving the user.

5) What is useState in React?

  useState is a React Hook used to manage state inside a functional component. 
  It returns the current state value and a function to update it. 
  When the state is updated, React re-renders the component.

  example:
  const [name, setName] = useState("");

  Here name is the state and setName updates it.

7) What is middleware in Express?


    Middleware is a function that runs during the request-response cycle.
    It can access the request and response objects 
    and can either modify them, end the response, or 
    pass control to the next middleware using next().

used async/await because database operations and API requests are asynchronous.

   const dogResponse = await fetch(

9) HTTP status codes?

   Why did you use 201, 400, 409 and 500 in your API?

   201 means the resource was successfully created. 
   400 is used when the client sends invalid or missing data. 
   409 indicates a conflict, which I used when the user already exists. 
   500 indicates an unexpected server-side error.

10) find() vs findOne()

    find() returns an array of matching documents, 
    while findOne() returns the first matching document or null 
    if no document is found. In my assignment, I used findOne() to check whether 
    a user already exists, and find() to retrieve the users.

What is the difference between PUT and PATCH?"

PUT is generally used to completely replace or update a resource, 
whereas PATCH is used to partially update a resource. 
For example, if a user has firstName, lastName, and DOB, 
with PUT I would normally send the complete updated user data. 
With PATCH, I could update only the firstName without sending the other fields.

PUT:
in postman
  PUT /user/123
  {
    "firstName": "Ankit",
     "lastName": "Shinde",
      "dob": "1998-05-10"
  }   

  PATCH:
in postman
   PATCH /user/123
    {
      "firstName": "Rahul"
    }

i) If they ask: "Which one did you use in your assignment?"

I used PUT for the update operation because my update endpoint expects 
the complete set of user fields—firstName, lastName, and DOB.

Remember this

PUT = complete update
PATCH = partial update
